# MCP 图片读取与会话展示

Agent 平台支持两种图片输入：MCP 工具直接返回 `image` 内容，或者工具返回资源引用后由 Agent 按需读取。Debug 和已发布应用共用 MCP Runtime Tool Factory、原生图片工具结果及 Chat 图片组件。

## 使用流程

1. 为 Agent 绑定知识库 MCP，允许 `search_chunks`，以及需要的 `get_document` / `get_chunk` 工具。
2. 平台为每个绑定的 MCP Server 派生一个 `mcp_read_resource_<server-id>` 工具，无需在远端注册这个工具。
3. 搜索工具返回标准 `resource_link` / 内嵌资源 URI 后，平台把可读取 URI 和读取工具名附入工具结果。现有 SKDY RAG 的 `document_id + asset_ids`、文档 presentation 的 `related_assets` 也会映射到 `rag://documents/{document_id}/assets/{asset_id}`，无需先修改知识库服务。
4. Agent 根据问题选择图片，使用对应工具和确切 URI 读取。图片以原生 image 内容传入运行时，正文上方自动显示“相关图片”，支持白底缩略图与放大预览。

读取工具只能访问**当前会话、同一个 MCP Server 返回过的资源引用**。引用缓存最多保存最近 256 条。运行时重建时，在首次模型调用前从同一份已授权的结构化会话历史恢复引用与来源信息；运行中的会话不重复回放历史。已保存图片的历史展示不依赖这个缓存。

恢复只接受与工具调用 ID/工具名配对的成功 MCP 结果，核对当前绑定工具、平台记录的服务 ID 与资源读取工具名。用户消息、助手正文、失败结果、无来源或来源冲突的结果不会授权资源。已保存的旧平台 `resources.tool/uris` 格式也按所属读取工具核验。资源读取仍实时检查服务状态、冻结 revision，并由远端校验当前凭据与文档归属；恢复历史不代替鉴权。

若旧引用已被上下文压缩移除、结果 JSON 被截断，或超过最近 256 条，则仍需重新检索/获取详情发现引用，不能从自然语言摘要或历史回答推断授权。

## 平台侧的取图引导

平台会自动补充以下引导，不需要修改 MCP Server 接口、远端工具描述或逐个修改 Agent 提示词：

- 每个运行时 MCP 工具的描述标明所属服务，保留远端原始描述；资源读取工具说明先查询、再原样使用 URI、不要猜测本地路径和跨服务试错。
- 绑定 MCP 的 Agent 在有效运行时提示词中附加统一图片规则，保存的 Agent prompt 不改写；Debug 和已发布应用共用此逻辑。
- 结果中的 `source` 标明服务，`resources.read_tool` 指定读取工具，`resources.items` 提供确切 URI、文档 ID、图片 ID，以及已有的文件名和 caption。没有 caption 时不编造图片说明。
- `query_knowledge_hub` 等仅返回文字和 document_id 的结果会附上 `resource_guidance.next_action`。只命中一个文档且允许 `get_document` 时，直接给出工具名及 document_id 参数；`[IMAGE: ...]` 不会被当成可读取 URI。
- 地址未发现时，错误说明如何获取文档关联资源；资源属于其他已绑定服务时，错误给出正确的读取工具和参数。被拦截的错误地址不会发送到 MCP Server。
- 本次结果最多附 16 个资源或 8 个文档引导项，并标明截断；会话内实际发现的引用仍按最近 256 条保留。

RAG 侧可后续补充更完整的 caption、章节或页码，提升选图准确率，这不是取图链路的必需变更。

## 权限与连接

- 读取操作继续检查 MCP Server 当前启用状态和绑定的冻结 revision。
- 资源请求通过官方 SDK `resources/read` 发到原 MCP endpoint，沿用原服务端凭据、网络策略、超时和响应大小限制，不把 URI 当作 HTTP 下载地址。
- 不把 MCP Token、外部服务凭据传给浏览器。
- 读取操作记入现有 MCP 调用审计；审计不保存图片字节或工具参数。
- 派生工具名参与运行时 allowlist 和 MCP 工具类型识别。

## 图片和持久化

支持 PNG、JPEG、GIF、WebP；检查 Base64、文件头与 MIME 是否对应。第一版每次工具结果最多 4 张图，解码后的图片总量最多 1 MiB；文字独立使用 `toolResultMaxBytes`，不会截断图片 Base64。超限或非法图片返回工具错误，由 Agent 继续处理。

复用已有会话事件保存原生图片内容，不新增独立 Artifact 存储或图片公开地址。工具结果中的图片随现有 `tool/result` 事件持久化；模型历史恢复、Debug 会话重建和发布页历史读取都复用这份数据。会话的已有访问权限控制历史图片的读取，来源 MCP 后续禁用会阻止新的资源读取，不会撤销已进入会话的历史内容。

这意味着图片字节会增加事件大小和历史读取流量。大量图片、原图下载、独立图片生命周期以及超过 1 MiB 的原图应在后续迁移到 Artifact / 对象存储；本次不声称已实现这些能力。

模型本身需要声明支持图片输入才能识图。现有模型适配器会对纯文本模型使用“不支持图片”的占位说明；用户仍可看到工具返回的图片。预览图可能由运行时已有图片规范化逻辑处理，因此界面使用“图片预览”，不承诺未经处理的原始文件。

## Realtime 和恢复

发布页 `tool.started` / `tool.completed` 增加稳定 `toolCallId`；完成事件携带经过校验的图片内容。并行调用同一个工具、重复事件都按 call ID 更新，不按工具名称混合图片。

HTTP 历史读取把持久工具结果关联到本轮回复；WebSocket sync 同时重放图片工具结果和回复。图片展示来自成功的工具结果，失败工具不展示图片，不依赖模型生成图片链接。

图片会按资源 URI 关联检索结果中的文档名称与已有 caption，并将展示信息随图片保存。卡片有 caption 时展示图片说明，有文档名称时展示“来源：《文档名称》”；缺少信息时隐藏对应行，不用内部 MCP 工具名作为标题、替代文本或来源。旧图片没有保存这些信息时仅展示“相关图片”，不会反推来源或生成未经验证的原文链接。此变更无需修改 MCP Server。

图片区域固定在回复正文上方，成功取图后即可展示，后续解释文字在下方流式输出。工具图片缩放/格式转换保留来源信息，实时事件转换仅复制经校验的展示字段，避免大图处理后丢失文档来源。

## 验证

回归覆盖原生与内嵌资源图片、RAG 资源发现、跨服务引用隔离、伪造 URI、禁用服务、独立文字/图片预算、非法 MIME/Base64、图片数量上限、官方 SDK 的真实 HTTP 资源读取、并行调用、无文字增量的最终回复、历史恢复、图片去重及共用发布页展示。

上线需更新平台后端和 Web 前端，并重建使用旧运行时的会话。实际知识库文档的取图效果还需在对应 MCP endpoint、知识库授权和模型配置下联调。
