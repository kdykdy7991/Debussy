### P1 设计决策（重要）

- **上传通道**：HTTP multipart（新增 `busboy` 依赖，需 `PI_ALLOW_LOCKFILE_CHANGE=1`）+ `Authorization: Bearer <PI_WEB_TOKEN>`，复用 WS 的 Host/Origin/CORS；文件二进制不经过 WS。上传端点挂在 WS listener 的同一 httpServer（`httpHandler` 钩子）。
- **注入方案**：coding-agent `PromptOptions.attachments`（`{id,name,mediaType,path}`）。`prompt()`/`steer` 把内容读进 LLM 消息（文本限 256KiB、图片走 processImage），`_handleAgentEvent` 持久化 user 消息时替换为 `[附件: name]` 引用——transcript/JSONL 不含内容或暂存路径。
- **prompt/steer `attachmentIds`** 只接受已绑定且 `ready` 的附件，否则 `invalid_state`；未绑定附件被其他 session 引用 → `conflict`。
- **快照合并**：`normalizedSnapshot` 从 store 合并 session attachments（有才带字段，P0 快照形状不变）。
- **删除/解绑**：`remove_attachment` 标记 removed + 设置过期时间，保留期后清理，不立即删文件（保留历史引用）。未绑定上传 24h 过期清理。
- **web 端** attach scope=`session`（持久到手动移除）；`turn` scope 由协议支持、web 暂未用。

### P2 设计决策（重要）

- **检索只在服务端**：excerpt 一律来自服务端存储的 Chunk，客户端无法提交；Citation 同时校验 `sessionId`/`sourceId`/`chunkId`。
- **受控注入**：检索上下文是独立 context block，只拼接进 user 消息（`PromptContextBlock`），**不修改 system prompt**；transcript/JSONL 只存 `引用资料: <文件名>` 引用，不落 excerpt。首片段即使超预算也保留（回合至少有 1 个来源），预算按分数截断。
- **Source 与附件生命周期绑定**：text 附件 attach 后后台 `ensureSource`（幂等 + 并发去重）；引用仍在 indexing 的 Source 的 prompt 返回 `invalid_state`（"文件仍在处理"），不静默发空上下文；`remove_attachment` 同步标记 Source removed，不再参与检索。
- **回退路径保留**：非文本附件无 Source，走 P1 全量注入；检索结果为空时同样回退 P1。
- **词法检索**：BM25 + CJK 双字切分（无向量库），轻量英文复数还原（`dogs`→`dog`）提升召回。
- **恢复**：`citation_snapshot` 只在回合结束广播一次；快照 `citations` 只带最近一回合（不无限累积）；session reopen 从 `turns/<sessionId>.json` 恢复最近一回合 Citation（断线重连不重复）。

## P0 设计决策（重要，别回退）

- **事件日志采用 Approach B**：replay buffer 存在 `LiveSessionManager` 的 `eventLogs` map 里，**runtime dispose 后仍存活到保留期**（默认 2000 事件或 10 分钟，`sessionEventLogMaxEvents` / `sessionEventLogRetentionMs` 可配）。所以 detach→dispose 的既有语义不变（`disposeCount` 断言全保留），reopen 时 `eventLogFor` 采纳旧 log 续 sequence。
- sequence 从 **1** 开始；snapshot.lastSequence 无事件时为 **0**；`resume.afterSequence` 最小 0（"负数 sequence"→schema 拒）。`replayedThrough` = 最后重放的事件 sequence（reset 时为 lastSequence）。
- `resume` 会 attach 连接 + 重放缺失事件 + 返回权威 snapshot；`resetRequired: true` 表示 buffer 过期/未来 sequence，客户端整体替换。
- turnId 每次 `runOperation`（prompt/steer/abort/setModel/setThinking）重新生成，progress 事件按 live.currentTurnId 归属。
- client 端 `attachSession`/`acquireSession` 在 `getLastSequence>0` 时发 `resume` 而非 `attach`（自动恢复，无独立 resume API，见 README）。state.ts 的 `reset()` **不清** sequence（否则断线重连无法 resume）；serverId 变化时清空。
