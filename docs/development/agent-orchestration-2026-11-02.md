## 1. 背景与目标

依据本次用户确认，将 Published Agent 扩展为事件驱动的后台服务。工单后端配置提示词、模型和思考强度，提交告警与本次 Tool 凭据，异步查询结构化结论。无需用户姓名或账号映射，浏览器关闭不影响分析。

参考本地 DSH 文章与原型；前期调查见 [最小架构分析](./ticket-analysis-minimal-architecture-2026-11-02.md)。用户已确认本功能进入开发；本规格扩展 ROADMAP 中尚未纳入的事件工作编排范围，不代表自动满足原有发布门禁。

## 2. 范围

包含：服务端 Router、持久化事件/工作项/订阅/派工、单活动调度器、现有 Conversation 执行适配、工具参数凭据注入、报告校验、配置自动生效、控制台接入及工作项管理、接入文档。

不包含：常驻 LLM Router、语义归并告警、多 Worker 协作、分布式执行、Webhook、嵌入配置页。工单项目首期自行提供表单，通过服务端接口接入。

## 3. 当前行为

发布版本与 Conversation 已可持久化，完整 Turn 后 Runtime 可销毁重建。MCP 支持固定连接凭据、工具 allowlist 和进度审计。尚无业务事件去重、持久派工及报告契约。已有 lint 基线未通过，不得声称全仓静态检查通过。

## 4. 目标行为与 DSH 映射

- Source：已授权接入系统；Thread：接入系统 + 发布应用 + 告警 ID。
- Trigger：带唯一 eventId 的不可变告警事件。
- Ticket：工作项；Assignment：一次派工；Conversation：执行上下文。
- Subscription：工作项对告警事件流的显式关联。首期不自动扇出到不同权限工作项。
- Router：确定性准入、去重、创建/投递工作、派工、接收并交付报告。
- Worker：复用 ConversationService 和现有 Runtime，不增加第二套 Agent Loop。

补充信息必须指定 workItemId；工作项同告警且同接入方才可接收。执行期间新输入持久排队，下一 Turn 消费；技术重试继续原上下文，全新分析创建新工作项。

## 5. 方案调研与选型

| 候选 | 满足程度与成本 | 结论 |
| --- | --- | --- |
| 现有 Conversation/发布/MCP | 已具备状态、执行和工具边界，缺业务调度 | 复用，并以薄适配器封装 |
| 本地 DSH 原型 | 概念直接契合，但依赖 DSH、GitHub/飞书和另一套存储 | 借鉴生命周期，不复制运行时 |
| [pg-boss](https://github.com/timgit/pg-boss) | 成熟 Postgres 队列；只能替代派工调度，不能替代业务授权与结果对账 | 首期不新增依赖，后续作为 Dispatcher 可替换实现 |
| [Temporal](https://docs.temporal.io/develop/typescript) | 持久工作流及 Worker，但需要另一套服务与执行模型 | 当前单机、短时研判范围不采用 |
| 最小 Postgres 派工适配 | 派工记录本身作为队列，与事件原子提交 | 仅实现本领域需要的领取与恢复，不建设通用队列框架 |

外部文档于 2026-11-02 查询。SQL 事务、进程独占、重复事件及结果恢复通过隔离数据库测试验证；若不能可靠保证这些条件，停止扩展并重新选择调度器。

## 6. 技术与接口契约

服务端新增 `orchestration/`；Postgres 迁移追加，不修改已有迁移。原有聊天与 Embed 入口保持独立。

管理员接口 `/api/admin/v1/orchestration`：创建、列出及更新接入配置，轮换/停用调用凭据，查看工作项详情，取消/重试。新凭据只在签发响应中显示。

业务接口 `/api/orchestration/v1`：

| 方法与路径 | 请求/语义 |
| --- | --- |
| GET /configuration | 当前生效配置与允许模型 |
| PUT /configuration | expectedRevision、systemPrompt、modelId、parameters；只开放白名单字段 |
| POST /events | eventId、alarmId、input、可选 workItemId、credentials、凭据有效期；返回 202 与 workItemId |
| GET /work-items | 可按 alarmId 查询，按接入范围隔离 |
| GET /work-items/:id | 状态、派工、当前报告及输入覆盖信息 |
| POST /work-items/:id/retry | 失败恢复；同一个工作项新派工 |
| POST /work-items/:id/cancel | 终止工作项及待执行派工 |

接入凭据标识系统，不随用户切换；Tool key 是独立的任务凭据。所有凭据走后端，不放进 URL。业务接口不开放浏览器 CORS，不要求提供 userId/name/roles。

接入配置绑定已发布应用，生效版本单独冻结。配置更新复用控制面保存与编译精确 Revision；只有编译成功后以 CAS 更新接入配置指针才算生效，失败保持旧指针。报告契约、工具注入规则和执行限制随工作项冻结。创建配置时由管理员确定模型白名单和工具参数映射。

报告 v1：summary、causes、evidence、recommendations、uncertainties。数组内容为字符串。JSON/字段/类型/长度不合格为失败；证据不足可明确写入 uncertainties。

## 7. 状态与恢复

工作项状态：queued、running、succeeded、failed、cancelled。失败码区分凭据失效、报告非法、执行失败与未知中断。

第一版调度器使用独占连接的数据库 advisory lock，禁止多进程同时驱动同一套编排；派工原子领取，同工作项不并发。重启先核对已提交 Turn：有最终成功输出则恢复报告，无可靠终态则标记中断待显式重试，绝不盲目重放工具副作用。排队输入仍保留。

取消先保存取消事实，再中止执行；迟到结果不得覆盖取消。下一派工只在前一次执行真正结束后开始。队列和执行有超时；缺失/过期凭据不能落到共享连接 key 上。

## 8. 安全与兼容

接入方认证范围由服务端确定。每个工作项独立服务身份/Conversation 归属，避免通过共享业务账号读取别的凭据范围下的历史结果。所有查询和操作检查 tenant/integration/app。

凭据独立加密存储，以工作项/派工范围校验；Scope 只携带受信任引用。按 MCP Server + Tool + 顶层参数名绑定，向模型隐藏密钥字段，实际执行时注入并校验原始参数。复杂 JSON Schema 绑定首期明确拒绝。工具回显、错误、进度和报告也必须避免泄漏密钥。

不改变现有 MCP 固定认证、工具 allowlist、网络策略和 Conversation 的唯一持久事实源。首期只读工具用于告警研判；有副作用调用不承诺恰好一次，需对方提供幂等支持。

## 10. 验收条件

### 控制台可用性改进（2026-11-02 用户反馈）

- 主页面分为工作项与接入系统两个视图，支持搜索、状态/来源筛选及后台刷新；统计只描述当前加载的最近工作项。
- 创建接入在分步抽屉中完成：按名称选择已发布 Agent、选择允许模型、配置可选的多条任务凭据映射。不再要求手填应用/MCP/模型标识。
- 工具授权支持按 MCP 服务和密钥参数批量选择工具，支持全选/取消全选，共用一个请求凭据名称。仅绑定当前发布范围内支持该参数的工具；重复应用更新相同工具参数，不生成重复映射；其他服务/参数映射保留。生成结果可展开逐条调整，所有映射仍按原协议提交，最多 128 条。相同凭据名称在事件请求中只需提供一次，新发布的工具不会自动获得授权。
- 新增管理员只读 catalog 接口，从同租户的有效发布快照提供 Agent、模型能力、工具及可绑定参数名称；不返回完整 Schema、默认参数或凭据。
- 分析配置、结果详情、接入说明和一次性凭据使用独立抽屉；弹层可键盘操作，关闭恢复焦点，未保存修改需确认。
- 思考选项来自实际模型能力；保存前显示生效范围，发生版本冲突时保留草稿，并提供重新加载入口。
- 轮换凭据与取消工作须确认；凭据可复制且不持久存储。读取/提交错误出现在相应操作区域，禁止以空列表掩盖加载失败。
- 浏览器验证覆盖新建、多条映射、配置保存/冲突、筛选、结果读取、取消/重试确认、凭据显示与窄桌面布局。

1. 首次提交立即返回工作项，后台分析完成并可查询结构化报告。
2. 重复 eventId 不重复工作，不同内容重用 eventId 返回冲突。
3. 跨接入方/租户不能查看、补充、取消或重试工作。
4. 两个并发工作项各用其 Tool key；模型工具 Schema、事件、错误和报告不包含 key。
5. 配置版本冲突可识别，失败不影响旧生效版本，运行中工作不漂移。
6. 重启不丢排队工作；已完成 Turn 不重复执行；不确定执行明确暴露为失败。
7. 补充输入不会被旧派工错误标记为已处理；取消不被迟到成功覆盖。
8. 控制台操作使用真实服务端状态，凭据不会在后续读取响应中回显。
