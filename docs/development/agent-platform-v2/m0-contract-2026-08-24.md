### 2.1 每轮性能（V2-README §4.1）

```ts
interface TurnMetrics {
  inputTokens: number;
  outputTokens: number;
  cacheReadTokens: number;
  cacheWriteTokens: number;
  requestStartedAt: string;
  providerStartedAt: string;
  firstOutputAt: string | null;
  completedAt: string;
  ttftMs: number | null;
  generationMs: number | null;
  totalLatencyMs: number;        // completed - requestStarted；恒有值
  outputTokensPerSecond: number | null;
}
```

推导由纯函数 `deriveTurnMetrics` 统一完成：

```text
ttftMs             = firstOutputAt - providerStartedAt（无 firstOutput → null）
generationMs       = completedAt   - firstOutputAt   （无 firstOutput → null）
totalLatencyMs     = completedAt   - requestStartedAt（恒有值）
outputTokensPerSec = outputTokens / generationMs * 1000（无输出或 generationMs 不可用 → null）
```

首个可展示文本增量才计 TTFT；thinking、心跳、Tool 事件不算首 Token。

### 2.2 上下文快照（V2-README §4.2）

```ts
interface ContextUsageSnapshot {
  usedTokens: number;
  contextWindow: number;
  remainingTokens: number;
  reservedOutputTokens: number;
  usagePercent: number;
  measurement: "exact" | "estimated"; // 无法精确 tokenizer 时必为 estimated
  breakdown: {
    systemPrompt: number;
    skillInstructions: number;
    toolDefinitions: number;
    conversationMessages: number;
    toolResults: number;
    retrievalContext: number;
    attachments: number;
  };
}
```

快照在最终模型请求组装完成、发送之前生成。`breakdown` 分项之和必须解释
`usedTokens`；不可归类内容须新增明确字段，不得塞入 `conversationMessages`。

### 2.3 单会话查询响应

- `GET /api/control/v1/conversations/:id/metrics` → `ConversationMetricsResponse`：
  `{ conversationId, stats, items[] }`。旧会话无指标时 `stats.available=false`、
  `items=[]`，不伪造 0。
- `GET /api/control/v1/conversations/:id/context` → `ConversationContextResponse`：
  `{ conversationId, available, latest, atSequence }`。`latest=null` 表示无快照。

均值/分位只统计“有值样本”（`null` 不写成 0），并返回样本数；见
`computeConversationMetricsStats`。分位采用 nearest-rank，无外部依赖。

## 3. 错误码

沿用控制面错误信封 `ControlErrorEnvelope.error = { code, message, requestId, retryable }`
（`publishing/control-http.ts`）。本里程碑新增冻结错误码：

| code | 含义 | httpStatus | retryable |
|---|---|---|---|
| `METRICS_UNAVAILABLE` | 会话从未采集到指标（旧会话/功能关闭） | 404 | false |
| `CONTEXT_SNAPSHOT_UNAVAILABLE` | 会话从未生成上下文快照 | 404 | false |
| `INVALID_METRICS_FILTER` | 查询参数非法（非本会话 id、无效 sequence/时间过滤） | 422 | false |

约束：跨租户/越权统一走既有 404 语义，不暴露资源归属。非法 reasoning 档位沿用已完成
`model-parameters` 契约的 `INVALID_MODEL_PARAMETERS`。

## 4. 事件顺序与空值语义

冻结事件顺序（单轮）：

```text
turn/start → context/snapshot → user/message → assistant/start
  → 首个可展示文本增量 → … → turn/end（携带 TurnMetrics）
```

- `context/snapshot` 必须在最终请求发送前持久化；查询端不得重新猜测历史值。
- `turn/end` payload 为 `TurnMetrics`（事件类型括号式命名）。事件命名权威枚举为
  `SESSION_EVENT_TYPES`；恢复路径（`context-restore.ts`）继续兼容 legacy 命名以读存量。
- 无值字段一律 `null`，不得写成 0 混入平均值；会话均值只统计有值成功轮次，同时返回样本数。

## 5. reasoning 契约（引用已完成规格）

reasoning 收敛与校验已在 `docs/development/model-parameters-2026-08-21.md`（已完成）
和 `packages/server/src/model-parameters.ts` 落地，并有测试
`packages/server/test/model-parameters.test.ts`。M0 不在 reasoning 新增代码，仅确认：

- 顶层只接受 `reasoning.enabled/effort`；非法档位与任何 sampling/generation 字段
  明确拒绝（`INVALID_MODEL_PARAMETERS`），不静默忽略；
- 生效优先级：会话 effort → Agent Revision 默认 → Provider/模型默认；
- 除 reasoning 外无 Revision/会话 override；固化生成参数走代码常量 → Runtime stream
  options → Provider adapter → payload，不由请求注入。

## 6. 数据库迁移与回退草案

迁移沿 `packages/server/src/persistence/postgres/migrate.ts`（`_migrations` + advisory
lock，只前向，无 down 执行器）与 `NNNN_name.sql` 命名。

M0 采用**扩 `turn/end` payload**，`conversation_events.payload` 为 jsonb，追加
`TurnMetrics` 字段**不需要 DDL**；仅 M1 采集落地后可考虑为 metrics 查询加部分索引
（如按 `(conversation_id, sequence)` 已存在 replay 索引），届时再追加向前迁移。

回退草案（不写破坏性 down）：

1. 采集/查询由特性开关 `PI_AGENT_V2_METRICS`（默认关）控制；关闭后旧行为与现在一致，
   已有的 jsonb 字段无害；
2. 若未来加索引，回退只做“关闭开关 + 索引非关键”：索引无需立即删除，属非破坏性；
3. 不做任何 down migration 删除列。数据可追溯。

## 7. 特性开关（名称与默认值）

| 开关 | 默认 | 说明 |
|---|---|---|
| `PI_AGENT_V2_METRICS` | `false` | 开启单会话指标采集与 metrics/context 查询接口 |
| `PI_AGENT_V2_REASONING` | `false` | 预留：若未来需对 reasoning 二次收敛/灰度 |

reasoning 当前为已启用产品能力（非特性开关）；`PI_AGENT_V2_REASONING` 命名先冻结，
M1 是否接由实现决定。chat-only 回退沿用现有 `runtimePolicy.profile` 机制。
