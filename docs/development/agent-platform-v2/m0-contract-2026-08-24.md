### 2.1 每轮性能（V2-README §4.1）

时间测量使用单调时钟，与墙上时间显式分离：

```ts
type TurnOutcome = "success" | "failed" | "cancelled";

interface TurnWallClockStamps {          // 仅展示/追溯，勿用于延迟减法
  requestStartedAt: string;              // ISO 8601 / UTC
  providerStartedAt: string;
  firstOutputAt: string | null;
  completedAt: string;
}

interface TurnMonotonicDelays {          // 相对一次请求开始的单调延迟（ms）
  providerStartDelayMs: number;
  firstOutputDelayMs: number | null;     // 无输出 → null
  totalElapsedMs: number;                // 恒有值
}

interface TurnMetrics {
  outcome: TurnOutcome;                  // 失败/取消时派生时序字段全部 null
  stamps: TurnWallClockStamps;
  inputTokens: number;
  outputTokens: number;
  cacheReadTokens: number;
  cacheWriteTokens: number;
  ttftMs: number | null;
  generationMs: number | null;
  totalLatencyMs: number;                // = monotonic.totalElapsedMs
  outputTokensPerSecond: number | null;
}
```

推导由纯函数 `deriveTurnMetrics` 统一完成，全部基于单调延迟（墙上时间戳不做减法）：

```text
ttftMs             = firstOutputDelayMs - providerStartDelayMs
                     （仅 success 且首 Token 存在且不早于 provider 开始，否则 null）
generationMs       = totalElapsedMs     - firstOutputDelayMs   （同上，仅 success）
totalLatencyMs     = totalElapsedMs                             （恒有值）
outputTokensPerSec = outputTokens / generationMs * 1000
                     （仅 success 且 generationMs>0 且 outputTokens>0，否则 null）
```

首个可展示文本增量才计 TTFT；thinking、心跳、Tool 事件不算首 Token。failed/cancelled
以 `outcome` 显式标记，其 `ttftMs/generationMs/outputTokensPerSecond` 一律 `null`，
不得写成 0 混入平均值。

### 2.2 上下文快照（V2-README §4.2）

```ts
interface ContextUsageSnapshot {
  usedTokens: number;
  contextWindow: number;
  remainingTokens: number;
  reservedOutputTokens: number;
  usagePercent: number;
  measurement: "exact" | "estimated"; // 无法精确 tokenizer 时必为 estimated
  breakdown: {
    systemPrompt: number;
    skillInstructions: number;
    toolDefinitions: number;
    conversationMessages: number;
    toolResults: number;
    retrievalContext: number;
    attachments: number;
  };
}
```

快照在最终模型请求组装完成、发送之前生成。`breakdown` 分项之和必须解释
`usedTokens`；不可归类内容须新增明确字段，不得塞入 `conversationMessages`。

### 2.3 单会话查询响应（分页与统计分离）

- `GET /api/control/v1/conversations/:id/metrics` → `ConversationMetricsResponse`
  `{ conversationId, stats, items[], nextAfterSequence }`。
  - 请求带 `ConversationMetricsQuery`：`afterSequence` 游标 + `limit`。
  - `items` 仅当前页（升序，`(afterSequence, nextAfterSequence]`）；`nextAfterSequence`
    即本页最后一轮的 `sequence`，作为下一页 `afterSequence`；为 `null` 表示无更多轮。
  - `stats` 为**整个会话**的聚合，服务端在完整轮记录上计算，**不得**由当前页 `items`
    推导。
- **分页边界（冻结）**：默认 `limit=50`，上限 `limit=200`（超上限钳制）；
  `afterSequence` 必须为正整数（首页省略），`limit` 必须为正整数；违反任一条 →
  422 `INVALID_METRICS_FILTER`。见 `CONVERSATION_METRICS_DEFAULT_LIMIT` /
  `CONVERSATION_METRICS_MAX_LIMIT` / `resolveMetricsPage`。
- `GET /api/control/v1/conversations/:id/context` → `ConversationContextResponse`：
  `{ conversationId, available, latest, atSequence }`。无快照时也返回 200，`latest=null`。

均值/分位只统计 `outcome === "success"` 且有值的轮次（`null` 不写成 0），并返回
`sampleCount`（= 全会话 success 轮数）；见 `computeConversationMetricsStats`。分位采用
nearest-rank，无外部依赖。

## 3. 错误码

沿用控制面错误信封 `ControlErrorEnvelope.error = { code, message, requestId, retryable }`
（`publishing/control-http.ts`）。本里程碑新增**候选**错误码：

| code | 含义 | httpStatus | retryable |
|---|---|---|---|
| `METRICS_UNAVAILABLE` | 指标子系统暂不可用（特性关闭/服务不可达） | 503 | true |
| `CONTEXT_SNAPSHOT_UNAVAILABLE` | 上下文快照子系统暂不可用 | 503 | true |
| `INVALID_METRICS_FILTER` | 查询参数非法（非本会话 id、非法分页参数、无效过滤） | 422 | false |
| `REASONING_INVALID_EFFORT` | 档位不在模型能力目录声明档位内 | 422 | false |
| `REASONING_NOT_CONFIGURABLE` | 调用方无权调整该会话思考强度 | 403 | false |

Skill / MCP 错误码见 §5b（`AGENT_V2_SKILL_ERROR_CODES`、`AGENT_V2_MCP_ERROR_CODES`，
含 `MCP_SECRET_NOT_CONFIGURED`）。映射见 `AGENT_V2_METRICS_ERRORS` /
`AGENT_V2_REASONING_ERRORS`。

空态与 unavailable 分界（候选）：

- 会话存在但无指标/快照数据 → **HTTP 200** `available=false`（成功形状，不是错误）；
- 指标/上下文子系统暂不可用 → **HTTP 503** `METRICS_UNAVAILABLE` / `CONTEXT_SNAPSHOT_UNAVAILABLE`；
- 会话不存在或跨租户越权 → HTTP 404 `CONVERSATION_NOT_FOUND`（既有语义，不暴露归属）。

非法 reasoning 档位沿用已完成 `model-parameters` 契约的 `INVALID_MODEL_PARAMETERS`（引擎
内部校验）；本里程碑的会话覆盖更新端点用 `REASONING_INVALID_EFFORT`/
`REASONING_NOT_CONFIGURABLE`（见 §5）。

## 4. 事件顺序与空值语义

冻结事件顺序（单轮）：

```text
turn/start → context/snapshot → user/message → assistant/start
  → 首个可展示文本增量 → … → turn/end（携带 TurnMetrics）
```

- `context/snapshot` 必须在最终请求发送前持久化；查询端不得重新猜测历史值。
- `turn/end` payload 为 `TurnEndPayload`：既有 `ok`/`usage` 保持不变（用量聚合仍读
  `payload->'usage'`），V2 顶层追加可选 `metrics`（`TurnMetrics`）。详情见
  `packages/protocol/src/admin-workbench-metrics.ts` 的 `TurnEndPayload` 说明。
- 事件命名权威枚举为 `SESSION_EVENT_TYPES`（`turn/end`、`turn/failed`、
  `turn/interrupted` 均为其成员；`turn/failed` 为实际被写入、已在枚举补齐）。
  恢复路径（`context-restore.ts`）继续兼容 legacy 命名以读存量，只读不写。
- 终态事件边界（`turnOutcomeFromTerminalEvent`）：`turn/end`→`success`、
  `turn/failed`→`failed`、`turn/interrupted`→`cancelled`；legacy
  `turn.end`/`turn.failed`/`turn.interrupted` 仅只读映射。非终态事件映射为 `null`。
- 单调时序校验：`providerStartDelayMs <= firstOutputDelayMs <= totalElapsedMs`
  （firstOutput 缺席除外）；乱序由 `validateTurnMonotonicOrder` 拒绝，`deriveTurnMetrics`
  抛错，不静默忽略。
- 无值字段一律 `null`，不得写成 0 混入平均值；会话均值只统计 `success` 有值轮次，
  同时返回 `sampleCount`。

## 5. reasoning 契约（引用已完成规格）

reasoning 收敛与校验已在 `docs/development/model-parameters-2026-08-21.md`（已完成）
和 `packages/server/src/model-parameters.ts` 落地，并有测试
`packages/server/test/model-parameters.test.ts`。M0 不在 reasoning 新增代码，仅确认：

- 顶层只接受 `reasoning.enabled/effort`；非法档位与任何 sampling/generation 字段
  明确拒绝（`INVALID_MODEL_PARAMETERS`），不静默忽略；
- 生效优先级：会话 effort → Agent Revision 默认 → Provider/模型默认；
- 除 reasoning 外无 Revision/会话 override；固化生成参数走代码常量 → Runtime stream
  options → Provider adapter → payload，不由请求注入。

**会话状态更新 + 权限 + 审计（本轮新增契约）**：

- 读取：`GET /api/control/v1/conversations/:id/reasoning` →
  `ConversationReasoningState`（`effort` 可为 `null` = 用 Revision 默认）。
- 更新：`PUT /api/control/v1/conversations/:id/reasoning`，请求体
  `ReasoningUpdateRequest { effort }`，响应 `ConversationReasoningState`。
- 权限边界：管理员调试会话（admin-debug）由 Admin Token 授权；已发布应用的企业会话
  由会话属主（终端用户/Embed 会话）调整自己的会话；跨属主/无权限 → 403
  `REASONING_NOT_CONFIGURABLE`。
- 档位校验：仅接受模型能力目录声明支持档位之一，否则 422 `REASONING_INVALID_EFFORT`。
- 审计：每次覆盖写 `conversation.reasoning-updated` 事件（before/after + 最终生效
  快照），可恢复、可审计；不改写 Agent Revision 或其它采样参数。见
  `AGENT_V2_REASONING_AUDIT_ACTION`。

## 5b. Skill / MCP 管理契约（候选，第三轮结构性修订）

见 `packages/protocol/src/admin-workbench-skills.ts` 与 `admin-workbench-mcp.ts`：

- **Skill**：`SkillSummary`/`SkillDetail`/`SkillRevisionSummary`/导入(`SkillImportRequest`)/
  校验/启用停用；错误码 `AGENT_V2_SKILL_ERROR_*`。
  - **绑定固定到不可变 Agent Revision**：`AgentBindingRef { agentId, agentRevision }`，
    `SkillBindingRequest.agentRevision`，`POST .../agents/:id/revisions/:revision/skills`；
    不随 Agent 后续 revision 漂移。
- **MCP**：`McpServerSummary`（含 `secretConfigured`）/`McpServerDetail`/创建更新
  (`McpServerUpsertRequest`)/测试(`McpTestResponse`)/同步 Tool(`McpSyncToolsResponse`)/
  Tool 白名单(`McpToolAllowlist`)/绑定(`AgentMcpBinding`，含 `agentRevision`)；
  错误码 `AGENT_V2_MCP_ERROR_*`。
  - **transport 未评审**：BE-3 ADR 定案前**不**把 transport 集合当公共契约导出；当前仅
    `streamable-http` 目标描述（`McpHttpTarget`），不含 stdio。
  - **Secret 只以引用保存**：配置为结构化 `McpServerConfig`/`McpHttpTarget`，凭据用
    `bearerTokenRef` 引用服务端 Secret 库，读取只回 `secretConfigured: boolean`，绝不含
    明文；引用未配好时拒绝（409 `MCP_SECRET_NOT_CONFIGURED`）。

## 6. 数据库迁移与回退草案

迁移沿 `packages/server/src/persistence/postgres/migrate.ts`（`_migrations` + advisory
lock，只前向，无 down 执行器）与 `NNNN_name.sql` 命名。

M0 采用**扩 `turn/end` payload**，`conversation_events.payload` 为 jsonb，在保留
`ok`/`usage` 的前提下追加 `metrics`（`TurnMetrics`），**不需要 DDL**；用量聚合继续
读 `payload->'usage'` 不受影响。采集实现（M1）在持久化前用 `turnOutcomeFromTerminalEvent`
+ `deriveTurnMetrics`（单调时钟）生成度量并写入。仅 M1 采集落地后可考虑为 metrics
查询加部分索引（如按 `(conversation_id, sequence)` 已存在 replay 索引），届时再追加
向前迁移。

权威事件枚举新增 `turn/failed`（实际已写入的事件）：`event_type` 为 text 列，枚举扩展
不产生 DDL/迁移；仅需测试与文档同步。

回退草案（不写破坏性 down）：

1. 采集/查询由特性开关 `PI_AGENT_V2_METRICS`（默认关）控制；关闭后旧行为与现在一致，
   已有的 jsonb 字段无害；
2. 若未来加索引，回退只做“关闭开关 + 索引非关键”：索引无需立即删除，属非破坏性；
3. 不做任何 down migration 删除列。数据可追溯。

## 8. 五组联调 fixture（+ 分页两页）

  `afterSequence=0&limit=2` 返回 seq 41/42，`nextAfterSequence=42`；第 2 页
  `afterSequence=42` 返回 seq 43、`nextAfterSequence=null`。**两页 `stats` 相同**，
  都是全会话（turnCount=3）聚合，验证“stats 不从当前页推导”。
