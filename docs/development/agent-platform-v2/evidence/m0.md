## 已批准的架构决定

以下决定可以立即作为修订依据，不需要再次讨论：

### A1：M0 不修改 Runtime

批准 ADR D1。M0 只允许契约、fixture、原型和测试；`pi-runtime-adapter.ts`、`turn-executor.ts` 与正式采集留到 M1，且必须在修订后的 M0 通过后开始。

### A2：事件日志继续作为唯一事实源

有条件批准 ADR D2。Metrics 放入现有终止事件 payload，不新增第二事实表；必须保持现有 `{ ok, usage }` 兼容结构，建议新增嵌套字段 `metrics`，不得用 `TurnMetrics` 覆盖整个 payload。M1 查询性能不足时可增加非关键索引，但须先提交 explain 证据。

### A3：事件采用斜杠式新写入，legacy 只读

有条件批准 ADR D3。所有新事件使用 `SESSION_EVENT_TYPES` 的斜杠式名称；legacy 点式事件仅用于读取存量。后端必须先补齐成功、失败、取消的权威终止事件映射和兼容期限，再视为冻结。

### A4：Metrics 开关默认关闭

批准 `PI_AGENT_V2_METRICS=false`。不批准提前冻结未使用的 `PI_AGENT_V2_REASONING`：reasoning 已是现有能力，除非 M1 提交明确灰度需求、控制边界和测试，否则不得增加无实现的环境变量。

### A5：迁移只向前

批准 ADR D5。回退采用关闭开关和保持向后兼容的数据结构，不写破坏性 down migration。

### A6：Embed resize 的有效范围

`height` 必须是 `1..POST_MESSAGE_RESIZE_MAX_HEIGHT` 的整数；`0` 不代表折叠，必须在 protocol decode 边界拒绝。高度上限以 protocol 常量为唯一来源，SDK 不复制第二个 magic number。

### A7：Launch Token 的内存边界

销毁或首次发送后断开字符串引用即满足当前要求；不采用覆写为 `"\0"` 的伪清零方案。硬性要求仍是 Token 不进入 URL、DOM、持久化存储、日志或错误上报。

### A8：Embed SDK 包与公开 API

M1 正式 package 使用 `@earendil-works/pi-embed-sdk`，公开命名导出 `createEmbed` 和 `EmbedInstance`，不使用 default export。postMessage 首期保持 v1 兼容扩展；没有明确破坏性需求不得升 v2。正式 package 创建属于 M1，不在 M0 原型中实施。

### A9：Fixture 适配边界

fixture 只存在于测试/开发入口，通过单一 typed adapter 暴露与真实 API 相同的读模型；不得进入生产 bundle，不在组件内散落 mock 分支，不使用占位业务数字。前端可在第一批 DTO 冻结后建立适配层。

### A10：内部网络范围

发布对话页只服务团队或企业内部成员，不规划公网。移动端验证仍覆盖电脑 Chrome、Android Chrome 和 iOS Safari，但不引入公网部署、外部 SLA 或外部客户容量要求。

## 阻断项

### B1：轮次结果和聚合样本语义不完整

负责人：后端

`ConversationTurnMetric` 缺少成功/失败/取消结果，`TurnMetrics.totalLatencyMs` 又恒为 number；当前 `sampleCount` 的过滤条件永远为真，无法实现“只统计有值成功轮次”。修订要求：

- 增加明确的 `outcome`，或提供等价且可验证的终止状态；
- 明确失败、取消、Tool-only 的显示和聚合规则；
- 所有聚合字段只纳入契约允许的样本；
- 增加失败、取消、无文本和混合样本测试。

### B2：单调耗时与墙上时间混用

负责人：后端

当前 `deriveTurnMetrics` 用 epoch ms 同时生成 ISO 时间并计算耗时，不满足“单调时钟计算耗时”。修订要求：展示/审计时间使用 wall clock，TTFT/generation/total latency 使用 monotonic duration；定义二者采集点和持久字段，增加墙上时间回拨不影响耗时的测试。

### B3：终止事件 payload 兼容性未冻结

负责人：后端

现有 `turn/end` payload 包含 `ok` 和 `usage`。修订契约必须明确 `metrics` 的嵌套位置，证明 Usage 聚合仍读取原路径，并定义失败/取消终止事件是否携带 metrics。

### B4：空状态与错误码冲突

负责人：后端；总架构师复核

API 示例使用 `200 + available=false` 表达旧会话无数据，错误码表又定义 404 `METRICS_UNAVAILABLE`/`CONTEXT_SNAPSHOT_UNAVAILABLE`。冻结语义为：

- 已存在会话但无历史数据：HTTP 200，`available=false`；
- 会话不存在或跨租户：统一 HTTP 404，不泄露归属；
- 服务故障：HTTP 503；
- 非法过滤：HTTP 422。

后端应删除未使用的 unavailable 错误码，或提出不冲突的新用途并重新评审。

### B5：逐轮列表缺少分页

负责人：后端

`items[]` 不允许无界返回。补齐 cursor/sequence、排序方向、默认/最大 page size、下一页标志和非法 cursor 语义；fixture 与测试必须覆盖至少两页。

### B6：事件失败/取消命名与 legacy 边界未完成

负责人：后端

现有代码仍读取/统计 `turn.failed` 等点式事件，而权威枚举包含 `turn/end`、`turn/interrupted`。必须形成成功、失败、取消映射表，明确新写入名称、旧读取名称、审计/统计口径和兼容期限。

### B7：M0 契约状态标记过早

负责人：后端

总架构师尚未批准时，`m0-contract` 不得写“状态：可开发”“冻结 DTO”“M0 已批准”。改为“候选/待评审”，ADR 的“后端自检”须有实际勾选和提交证据；本轮通过后再统一改为冻结。

### B8：M0 其余契约尚未提交

负责人：后端提出；总架构师批准；前端复核可消费性

当前只覆盖 Metrics/Context。仍需处理前端问题清单中的 reasoning 会话持久化、Skill DTO、MCP DTO、Secret 替换、Tool allowlist、统一错误信封和 API 权限。可以分为 M0-A/M0-B 候选审查，但进入对应 M1/M2/M3 实现前必须先冻结该能力契约。

### F1：SDK 多实例测试未真实共享 window

负责人：前端

当前 `envA = makeEnv()`、`envB = makeEnv()` 生成两个独立 FakeWindow，不能证明同一宿主页上的两个实例互不串扰。修订为两个 iframe/实例共享同一个 FakeWindow 和 handler 数组，并验证 A.destroy 不移除 B 的监听器。

### F3：原型报告链接与范围描述需修订

## 对前端契约问题的阶段性答复

- Q1：Metrics/Context 是 Control Plane 管理接口，使用管理员鉴权；不是 Conversation-scoped token。
- Q2：服务端返回聚合和分页逐轮明细；前端不自行聚合。仅纳入成功且字段有值的样本。
- Q3：旧会话由服务端返回 `available=false`；前端不根据 `createdAt` 推断。
- Q4：不可归类内容必须新增明确字段并升级契约，不放入 `conversationMessages`。
- Q5：首版模型目录保持现有 reasoning capability；没有实际参数时不增加通用步长/互斥字段。
- Q6：会话 reasoning 覆盖必须服务端持久化；具体存储/API 由后端第二批候选提出。
- Q7：Admin 与 Embed 可以使用不同路由和权限，但必须共享同一服务语义、校验器和错误码。
- Q8～Q15：等待后端 Skill/MCP 第二批契约候选，不允许前端先定义。
- Q16：按 A8 冻结为 `@earendil-works/pi-embed-sdk`、`createEmbed`、`EmbedInstance`。
- Q17：控制台示例与 SDK 测试/文档使用同一源码片段或生成来源，避免双份手写漂移；默认展示 mount、ready、error、destroy。
- Q18：Admin 控制接口统一沿用 `{ error: { code, message, requestId, retryable } }`；Embed 保持其受限错误协议，不强行共用 Admin 信封。
- Q19：DTO 变化先运行 protocol build/test 两套 tsconfig 类型检查和指定 protocol 测试；不存在的 `npm run typecheck --workspace=@earendil-works/pi-protocol` 不得写入文档。
- Q20：第一批 Metrics/Context 修订候选应在本轮整改后立即提交；Skill/MCP 可以分批冻结，但不得越过门禁实现。
