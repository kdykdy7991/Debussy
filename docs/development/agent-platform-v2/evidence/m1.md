## 后端阻断项

### B1：当前 TTFT 是 burst 完成时间，不能作为真实 TTFT 发布

同步 `TurnExecutor` 只在整个结果返回时暴露文本，候选把 `firstOutputAtMs = completedAtMs`，因此 `ttftMs` 实际等于 Provider 整体调用耗时、`generationMs=0`、tokens/s=null。它对同步 burst 路径的“首次可展示时刻”是诚实观测，但 UI 无字段可区分 burst 与真实流式 TTFT，会把两种口径混为同一个会话统计。

处理要求：在实际 AI/stream 层暴露 provider-start 与首个可展示文本增量回调并接入采集；用 deterministic faux provider 做端到端断言。真实触点完成前，不得把 burst 样本写入正式 `TurnMetrics` 聚合；可以只写 context snapshot，或不写该轮 metrics。不得新增未冻结字段静默区分口径。

### B2：上下文快照不代表最终模型请求

候选在 `user/message` 持久化之前生成快照，输入只含历史消息；当前用户 `input.text`、随后得到的 retrieval context，以及可用的 tool result/attachment 来源都没有计入。契约要求在最终模型请求组装完成、发送之前采集，当前数值会系统性低估。

处理要求：在不改变事件序列契约的前提下，先完成本轮请求所需的检索/组装，再从与 `turnExecutor` 相同的输入来源估算并持久化；至少包含当前用户消息与 retrieval context。无法获得的分类才允许写 0，并保持 `measurement="estimated"`。补测试证明当前输入与 retrieval 会增加对应 breakdown，且各项之和等于 usedTokens。

### B3：分页末页 cursor 错误

`getConversationMetrics` 只要当前页非空就把最后 sequence 写入 `nextAfterSequence`，即使已经没有下一页。现有测试反而把末页 `[4]` 期望成 cursor=4，与冻结契约“无更多数据为 null”冲突。

处理要求：用 `limit+1` 或完整 rows 判断 hasMore；只有确有下一页才返回最后可见 sequence，末页返回 null。补齐刚好满页、非满末页、空越界页三种测试。

### B4：持久 payload 校验名义保守、实际过宽

`readStoredTurnMetrics` 只验证 outcome，`readStoredContextSnapshot` 只验证 usedTokens，随后整体强转 DTO。异常/旧 payload 可把 NaN、负数、缺 breakdown 等带入聚合或 UI。

处理要求：共享 protocol decoder/schema 优先；若 M1 暂无 schema，至少逐字段校验有限非负数、nullable 字段、stamps、breakdown 完整性和 usedTokens 分项守恒。非法 payload 当作无数据并测试。

## 前端阻断项

### F1：Fixture 被直接打入生产页面

`conversation-detail.tsx` 生产代码直接 import `loadFixture/get*TabData`，切换 Tab 后固定加载 fixture，新增的 `ConversationsApi.getMetrics/getContext` 实际未被页面调用。这违反 M0 A9“fixture 只在测试/开发入口、不得进入生产 bundle”。

处理要求：页面默认走真实 API；fixture 通过显式 dev/test 注入接口提供，生产构建不可 import fixture 数据。adapter 应负责把 API 成功/错误映射成 `DataState`，而不是让组件知道 scenario。

### F2：Context 百分比渲染放大 100 倍

协议和后端的 `usagePercent` 已是百分数（例如 3.75），`ContextSnapshotCard` 又乘以 100，最终显示 375%。直接格式化 `usagePercent` 即可，并补组件渲染测试。

### F3：占位快照伪造合法 loaded 数据

`loaded-with-snapshot` 使用 contextWindow/used/remaining 等全 0，并标记 `available=true`。这既不是合法真实快照，也会让页面显示 `0 / 0 tokens`；“不写业务数字”不等于可以用 0 冒充 loaded。

处理要求：状态壳使用 empty/partial，不构造 loaded 假快照；需要测试 loaded 渲染时，从后端已批准 fixture JSON 经 typed adapter 读取真实一致样本，且仅在 dev/test 注入。

### F4：页面交互仍是占位行为

分页与刷新按钮的回调都是 no-op/onRetry，未使用 nextAfterSequence；六态只有分支代码，没有组件级测试证明状态可达。作为“骨架提交”可保留，但不能声称已真实联调。

处理要求：接真实 API 后实现首次懒加载、重试、分页追加、会话切换取消/忽略旧请求；为 loading、empty、loaded、error 和分页至少增加组件测试。
