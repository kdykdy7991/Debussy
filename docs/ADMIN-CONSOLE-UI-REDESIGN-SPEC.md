# 管理员控制台 UI 重构规格（首版）

> 状态：已确认，待实施
>
> 适用范围：`runtimes/pi/packages/web/src/admin/`
>
> 本文覆盖 UI 信息架构与视觉系统；不改变既有租户隔离、发布安全、会话日志与 Embed 独立构建的服务端约束。

## 1. 目标与边界

面向企业网站接入 AI Agent 的管理员，提供从 Agent 设计、调试、发布、用量核对到问题追溯的单一工作台。

首版追求低认知负担，不做运营大盘、实时监控、复杂 BI、成本分摊、多角色管理或批量操作。管理员必须能在任一页面清楚知道自己处理的是管理员调试，还是线上企业用户数据。

## 2. 一级导航

左侧固定六项，顺序不得随页面变化：

1. **Chat**：管理员调试，不影响线上用户。
2. **Agent 设计**：配置、保存 Revision、查看关联发布应用。
3. **发布**：创建企业网站应用、预览、上线、回滚与接入管理。
4. **Usage**：Token 与对话消耗的汇总和按 Agent 归因。
5. **Session 日志**：线上企业用户 Conversation 的检索、追溯和导出。
6. **设置**：租户、管理员访问、会话保留策略与连接配置。

默认路由为 **Chat**。一级导航不再使用含义模糊的“应用”；PublishedApp 是“发布”模块下的核心对象。

```text
Agent 设计 → Chat 调试 → 发布到企业网站
                            ↓
                       Usage 核对
                            ↓
                    Session 日志排障
```

## 3. 全局框架

- 固定深色窄侧栏：产品标识、六项导航、当前租户名称和设置入口。
- 明亮主内容区：每页仅有一个明确页面标题、简短解释和一个主操作。
- 所有数据页必须在标题下说明数据范围与更新时间；失败、离线、示例数据必须显式标示，禁止以模拟数据伪装生产数据。
- 将当前租户、当前对象名称和面包屑放在工作区顶部；不再使用全局右侧功能抽屉承载主要任务。
- 高风险操作（发布、上线、回滚、暂停、导出）使用独立确认对话框；普通浏览、筛选和轻量编辑在页面内完成。

## 4. 页面规格

### 4.1 Chat

**任务**：以指定 Agent 与指定 Revision 完成管理员调试。

首屏：

- 顶部上下文条：Agent 名称、Revision（或“草稿测试”）、模型、连接状态；固定提示“管理员调试，不影响线上用户”。
- 左侧次级栏：Agent 选择、新建调试对话、该 Agent 最近 DebugSession。
- 中间：消息、工具调用、附件与输入框。
- 顶部辅助操作：`进入 Agent 设计`、`查看关联发布应用`。

状态：未解锁、连接中、断线重连、无 Agent、空调试对话、发送失败均需独立页面/行内反馈。

### 4.2 Agent 设计

**任务**：创建或修改 Agent，然后保存为不可变 Revision。

列表：名称、当前 Revision、草稿状态、模型、关联发布应用数、最后更新时间。主操作为 `新建 Agent`。

详情：

- 顶部：名称、保存状态、当前 Revision、`保存 Revision`、`在 Chat 中测试`。
- 内容分区：配置、Revision 历史、关联发布应用。
- 关联发布应用行显示：应用名称、线上版本、发布状态，并链接至发布详情。

约束：未保存草稿不能发布；恢复历史 Revision 创建新草稿，不修改历史。

### 4.3 发布

**任务**：把某个已保存 Agent Revision 安全发布给一个企业网站应用。

列表：发布应用名称、状态（运行中／待发布／已暂停）、绑定 Agent、当前线上版本、接入站点数、最后发布时间。主操作为 `创建发布应用`。

应用详情首屏按以下顺序呈现：

1. 应用状态、绑定 Agent、当前线上版本、最近发布人和时间。
2. 明确主操作：`预览待发布版本` 或 `创建发布版本`；有待发布版本时才显示 `上线`。
3. 待发布变更：目标 Agent Revision、变更摘要、预览结果。
4. 接入信息：Public App ID、允许 Origin、接入站点、复制接入代码。
5. 线上版本与发布历史：时间线式列表，当前版本置顶，历史版本可回滚。
6. 入口：`查看该应用的 Session 日志`、`查看该应用 Usage`。

发布对话框只承载预览确认、上线确认、回滚确认；必须显示影响对象、当前/目标版本和接入 Origin。

### 4.4 Usage

**任务**：了解 Token 消耗归属与异常增长，不承担完整成本分析。

顶部：时间范围（今天／近 7 天／近 30 天）与数据更新时间。

汇总只显示三项：总 Token、输入 Token、输出 Token；可在数据模型准备好后增加“预估成本”，不作为首版阻塞项。

核心列表按 Token 降序展示：Agent 名称、总 Token、输入/输出 Token、对话次数、关联发布应用数、相对上期变化。点击 Agent 后显示其发布应用分布，并可跳转到该 Agent 或相关 Session 日志。

必须可区分管理员调试与线上企业用户用量；默认显示总量，筛选项只保留“来源（全部／线上／调试）”。

### 4.5 Session 日志

**任务**：定位一个线上企业用户对话的行为与错误。

列表默认按最近活动排序，展示：会话状态、来源发布应用、Agent、固定发布版本、最后活动时间、消息数/错误标记。首屏筛选仅保留搜索、发布应用、状态和时间范围；其他条件收进“更多筛选”。

详情：

- 顶部上下文：来源应用、固定版本、会话主体的脱敏标识、创建/最后活动时间。
- 概览、事件日志、Summary/续接链、附件四个分区。
- 导出作为次级危险操作，明确脱敏范围、导出格式和审计记录。

术语约束：本模块始终称“Session 日志（线上用户）”，不得与 Chat 的 DebugSession 混称。

### 4.6 设置

**任务**：管理控制台运行边界。

首版只分为：租户与连接、管理员访问、会话保留策略、Embed 默认配置。敏感值默认隐藏；修改 Base URL、保留期等影响范围必须在保存前解释后果。

## 5. Usage 数据归因契约

每一次模型调用需要可聚合记录：`tenantId`、`timestamp`、`agentId`、`agentRevisionId`、`publishedAppId?`、`publishedAppVersionId?`、`conversationId / debugSessionId`、`source`（`embed` 或 `admin_debug`）、`inputTokens`、`outputTokens`、`totalTokens`。

Usage 页面只能消费服务端聚合结果；前端不得由会话消息长度估算 Token。所有聚合必须能按 Tenant、时间范围、Agent 和来源过滤。

## 6. 视觉系统约束

### 6.1 定位

低到中等信息密度的企业工作台：参考 Vercel 的发布状态清晰度、Sentry 的异常优先级和 OpenAI Platform 的项目上下文；不复制任何一个产品的主题或布局。

### 6.2 强制规则

- 使用一个明亮中性底色、深色侧栏和单一品牌操作色；不得默认使用紫色渐变、发光效果或玻璃拟态。
- 选择一套无衬线界面字体、一套线性 SVG 图标与一套圆角尺度；图标不使用 emoji 或文本符号。
- 用分隔线、留白和排版表达分组；卡片只用于真正独立的对象或高风险确认，不堆叠“白底描边阴影卡”。
- 状态必须由文字加色彩共同表达；绿色只表示健康/已上线，琥珀表示待处理，红色表示失败/风险。
- 表格/列表以对象名称和状态为视觉锚点；不为了“显得专业”引入无意义图表、渐变 KPI 卡或自动播放动效。
- 交互只使用 150–220ms 的 opacity/transform 过渡；尊重 `prefers-reduced-motion`。

### 6.3 反模板化验收

- 不出现 AI 紫、青蓝渐变、发光边框或大面积玻璃卡。
- 不混用两套 token、两种圆角和多个图标家族。
- 不存在无标题的大面积留白、看似可点但无闭环的按钮，或未连接时伪装为真实的示例数据。
- 每页均有空、加载、错误、无权限和长文本溢出策略。

## 7. 实施顺序

1. 重建 Shell：六项导航、Chat 入口、统一顶部上下文和全局状态反馈。
2. 统一视觉 token 与基础组件：按钮、状态、表格/列表、筛选、对话框、空/错误/加载态。
3. 迁移发布详情与确认对话框，完成“Agent → 发布 → Session 日志”跳转链。
4. 新增 Usage 的数据契约、服务端聚合与前端列表。
5. 迁移 Chat、Agent、Session 日志和设置至同一组件体系。

## 8. 验收

- 管理员可从任何模块辨认当前租户、数据对象、数据范围和是否影响线上用户。
- Chat、Agent 设计、发布、Usage、Session 日志、设置均有可发现的一级入口。
- 发布、Usage、Session 日志之间可沿对象关系双向跳转。
- Token 可按 Agent 与来源正确汇总，且不会将管理员调试与线上用户数据混为一谈。
- 在 375px、768px、1024px、1440px 下无关键操作或表格信息被截断；窄屏表格允许横向滚动或切为行卡。
