# 质量策略与完成定义

本文定义 Debussy 功能完成、版本候选和正式发布所需的最低质量证据。单项功能的具体验收仍写入对应的开发规格。

## 质量原则

- 以可重复的证据判断完成，不以“本地看起来正常”或代码合并代替验收。
- 测试优先覆盖用户主链路、跨 Plane 契约、权限边界、失败恢复和版本追溯。
- 自动化测试不调用真实付费模型、不读取个人凭据；真实 Provider 验证单独执行并记录成本与环境。
- 示例、Mock 和演示数据必须可辨认，不能伪装成真实生产状态。
- 发现缺陷时修复根因；不得通过删除正常功能、放宽安全边界或隐藏错误来通过门禁。

## 功能完成定义

一个功能只有同时满足以下条件才可标记完成：

- 有明确背景、目标、范围、非范围和目标行为。
- 产品规则与 [`PRODUCT.md`](./PRODUCT.md)、[`PRD.md`](./PRD.md) 和 [`INTERACTION.md`](./INTERACTION.md) 一致。
- 影响的接口、状态、异常、安全和兼容性已写入功能开发规格。
- 对非简单通用能力完成了仓库能力、成熟外部方案和自研方案的比较；选择结果有最小验证证据和可解释理由。
- 新增第三方依赖已审查维护状态、精确版本、许可证、生命周期脚本、体积/性能、兼容性、安全风险和替换边界。
- 代码检查通过，相关自动化测试通过。
- 正常、空状态、加载、无权限、失败、取消或重试等适用状态均已验证。
- 新增遥测不包含凭据、完整用户内容或其他禁止记录的信息。
- 验收证据包含执行环境、版本/提交、命令或步骤、结果和遗留风险。
- 用户可见行为变化已同步更新产品文档或发布说明。

## 测试分层

### 静态门禁

Pi Runtime 在 `runtimes/pi` 执行：

```bash
npm run check
```

该命令覆盖格式与静态检查、依赖固定、TypeScript 导入、锁文件一致性、Web 类型检查和浏览器 smoke 脚本检查。它会修改可自动格式化的文件，执行前应确认工作区差异。

### 自动化测试

非 E2E 测试从 `runtimes/pi` 执行：

```bash
./test.sh
```

测试脚本使用隔离 HOME、临时目录和空凭据环境，避免读取个人 Agent 配置或调用真实模型。修改测试文件时还应从对应 package 运行该具体测试。

Python Voice Service 单元测试必须使用 FakeProvider，不下载模型、不调用 GPU。真实模型验证属于手动 smoke，不替代单元测试。

### 发布能力专项验证

Publishing MVP 已提供以下验证入口：

```bash
cd runtimes/pi
bash scripts/verify-publishing-mvp.sh
bash scripts/verify-publishing-browser.sh
```

专项验证覆盖静态门禁、发布、Embed、Runtime、协议、指标、日志脱敏、并发轮次及 iframe shell。真实模型对话、长连接容量和故障注入仍需根据发布范围单独执行。

### 人工产品验收

P0 主链路至少覆盖：

1. 创建或修改 Agent，保存新的不可变 Revision。
2. 导入并校验 Skill，配置 MCP Server、Secret，测试连接并同步 Tools。
3. 将固定 Skill Revision、MCP Revision 和 Tool allowlist 绑定到 Agent。
4. 使用已保存 Agent 完成管理员 Chat 调试和真实 MCP Tool 调用。
5. 创建发布应用版本，核对冻结能力后显式激活。
6. 从独立宿主页进入 Embed，使用已授权身份完成对话和 Tool 调用。
7. 在手机尺寸和真实手机浏览器中进入发布对话页，完成阅读、输入、发送、停止/重试及适用附件操作。
8. 在 Usage 中核对来源与 Token 归属，在 Session 日志中定位应用版本和 Tool 调用。
9. 执行暂停和回滚，确认现有 Conversation 的版本语义符合产品规则。
10. 验证跨租户、未授权 Tool、SSRF、Secret 脱敏、MCP 超时/断连和 Skill 非法导入。
11. 使用同一真实模型分别在管理员 Chat 和发布 Chat 发起回答：对照思考过程、正文逐增量动画、工具轨迹、Agent 状态与最终排版；除权限控制项外必须一致。
12. 刷新或断线恢复发布 Chat，确认已完成消息的正文、可公开思考和 Tool item 不因恢复而丢失或改变结构。

## 发布门禁

当前门禁面向团队日常使用的内部可用版本：必须保证文本 Agent 主链路基本稳定、问题可观察、版本可回滚、数据可恢复；不以实时语音、数字人或公网能力阻断首版。

### P0：必须阻断发布

- 主链路不可用或数据写入/读取错误。
- Tenant、管理员与终端用户信任边界可被绕过。
- 发布版本不可追溯、不可暂停或无法按设计回滚。
- 凭据、完整用户文本或敏感附件内容进入 URL、浏览器持久存储、日志或错误文案。
- 数据损坏、不可逆迁移或未准备恢复方案。
- 测试或产品界面用伪造成功掩盖真实失败。
- 发布候选未通过适用的自动化和人工 P0 验收。
- 发布 Chat 使用全文单帧 delta、丢弃模型已提供的思考内容，或与管理员 Chat 使用不同消息渲染语义。
- Skill/MCP 或 Tool allowlist 未固定到发布版本，导致旧版本或旧会话能力漂移。
- MCP Secret 出现在客户端、RuntimeSpec、消息事件、日志、导出或错误响应。
- 存在跨租户 Skill/MCP 访问、未授权 Tool 调用或可利用的 MCP SSRF 路径。
- Skill 导入可造成路径穿越、符号链接逃逸、非预期文件执行或无界解包。

### P1：原则上阻断，可由明确风险接受放行

- 非核心流程存在稳定复现的功能错误。
- 明显性能退化、资源泄漏或大范围体验问题。
- 可访问性、浏览器兼容或失败提示影响主要目标用户。
- 关键指标或日志不足以判断发布是否健康。

P1 放行必须记录影响范围、临时措施、负责人、修复期限和批准人。

### P2/P3：可随版本跟踪

- 有替代路径的局部体验、视觉或低频边缘问题。
- 不影响正确性、安全性和主链路的优化项。

## 非功能质量

### 安全与隔离

- 所有跨 Tenant 访问必须有拒绝测试。
- 管理员凭据与终端用户凭据使用不同信任链路。
- 上传必须验证身份、会话归属、配额、类型和扫描结果。
- 日志必须经过脱敏测试。

### 性能与容量

- 内部版本按约 10～20 名团队成员规划，正式容量目标为 20 个同时进行的文本对话。
- 已有门禁覆盖 30 个同时在途轮次、默认 3 轮，作为内部目标之上的最低安全余量。
- 仓库验证脚本指出的 1,000 条 Realtime 连接、30 分钟稳定性仍属于待完成发布证据。
- 正式容量目标必须由预期租户数、并发连接和模型/语音资源共同确定。
- 1,000 条 Realtime 连接和公网规模容量不作为当前内部版本的发布门槛。

### 兼容性

- 管理员入口与 Embed 入口分别构建和验证。
- 管理员工作台首版正式支持最新版稳定版 Chrome/Chromium 电脑浏览器。
- 发布给内部成员使用的独立对话页和 Embed Chat 首版正式支持最新版稳定版电脑 Chrome、Android Chrome 和 iOS Safari。
- Firefox 和电脑端 Safari 采用尽力兼容原则，相关缺陷不作为首版阻断项，除非同时影响正式支持浏览器或构成安全、数据问题。
- Embed 至少验证独立页面和两个不同宿主页，避免依赖单一宿主环境。
- 移动端至少覆盖窄视口、横竖屏、虚拟键盘、长消息、滚动、断线恢复和 iframe 尺寸变化。
- 模拟视口适合快速回归，但发布前必须分别使用真实 Android Chrome 和 iOS Safari 完成核心对话验收。

## 待确认

- 自动化覆盖率是否设硬性目标；若设置，按模块还是全仓统计。
- P1 风险接受的批准角色和最长修复期限。
- 20 个并发文本对话的持续验证时长及性能回归允许幅度。
- 安全或数据专项检查的协助人与替代放行人。
