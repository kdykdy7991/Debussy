# 产品决策

本文件只记录已经接受、会长期影响产品的决策。

## D-001 管理员调试与线上用户会话分离

管理员 Chat 是调试环境；Session 日志和 Embed Chat 面向已发布应用的企业用户。两类会话在术语、权限和用量归属上保持隔离。

## D-002 发布应用显式绑定 Revision

线上应用使用不可变 Agent Revision。修改 Agent 配置不会绕过发布流程直接影响线上应用。

## D-003 真实状态优先

界面不使用模拟数据伪装真实连接或运行结果。离线、错误和未配置状态必须明确展示。

## D-004 管理员凭据不由前端界面管理

开发环境由代理注入管理员凭据，生产环境由网关注入。凭据不进入 URL、浏览器存储或可见错误信息。

## D-005 首个目标是内部可用的文本 Agent 闭环

首个目标版本供团队日常使用，要求文本 Agent 主链路基本稳定、可观察、可回滚和可恢复。当前不规划公网服务或对外 SLA。实时语音与数字人在文本主链路稳定后建设，不阻断首版。

## D-006 当前环境采用单机本地备份

开发和未来的内部试用使用同一台开发机。进入内部日常使用前，采用 PostgreSQL 与敏感身份材料每日备份、保留 14 天的本机方案；目标 RPO 为 24 小时，当前机器和本地备份可用时的目标 RTO 为 4 小时。当前尚未启用自动备份，不具备上述恢复保证。方案启用后仍接受不做异机或异地备份的风险，机器或同一存储介质损坏时不承诺恢复。

## D-007 管理入口与发布对话页采用不同适配范围

管理员工作台首版正式支持最新版稳定版 Chrome/Chromium 电脑浏览器，不要求手机端管理操作。发布给内部成员使用的独立对话页和 Embed Chat 必须适配移动端，首版正式支持最新版稳定版电脑 Chrome、Android Chrome 和 iOS Safari；Firefox 和电脑端 Safari 尽力兼容。

## D-008 内部版本按 10～20 人规模规划

内部版本面向约 10～20 名团队成员，首版容量门槛按 20 个同时进行的文本对话设计。现有 30 个同时在途轮次自动化测试作为最低安全余量，不代表更大规模容量承诺。

## D-009 产品负责人执行最终放行

当前由产品负责人承担最终产品验收和发布放行。技术、安全、数据或恢复门禁未通过时不得仅凭产品放行绕过；风险接受必须留有明确记录。

## D-010 发布范围仅限内部网络

当前产品不规划公网或面向外部客户发布。发布表示将 Agent 提供给团队或企业内部成员使用，当前运行在开发机，稳定后可迁移到局域网服务器。移动端适配用于内部成员通过手机浏览器访问，不改变内部网络边界。
