# 产品路线图

本文定义 Debussy 当前阶段的交付顺序和阶段完成条件。它不替代单项功能规格，也不承诺未经确认的发布日期。

## 路线图原则

- 先闭合“设计、调试、发布、使用、排障”主链路，再扩展外围能力。
- 每个阶段必须可独立验收、可观察、可回滚，不以页面存在或代码合并代替完成。
- Tenant 隔离、凭据安全、真实状态和版本可追溯属于所有阶段的发布门槛。
- 未进入当前阶段的能力不得阻断主链路交付；需要提前建设的共享契约除外。

## 当前阶段：开发基线

当前仍处于内部可用版本之前的开发阶段。目标版本要求文本 Agent 主链路基本稳定、问题可定位、版本可回滚，并能在当前机器仍可用时从本地备份恢复；不对外承诺生产 SLA 或机器级灾难恢复。实时语音与数字人不属于首个目标版本的发布门槛，在文本主链路稳定后进入后续增强。

开发和内部试用当前均在同一台开发机进行。R1 以单机可恢复为目标；迁移到局域网服务器属于稳定后的下一阶段，不在首版中假设已具备。

内部版本按约 10～20 名团队成员规划，首版容量目标为 20 个同时进行的文本对话。

当前仓库已具备以下基线：

- 管理员 Chat、Agent 设计、发布应用、Usage、Session 日志和设置的产品边界已确认。
- Control Plane、Data Plane、Runtime Plane、PostgreSQL 和 Redis 的稳定边界已定义。
- Agent Revision、Published App Version、企业 Conversation 和 Usage 的核心契约已定义。
- 管理员工作台与 Embed Chat 有独立构建和访问语义。
- 代码检查、隔离测试、发布专项回归、容量和故障注入验证已有可执行入口。
- 生产部署环境、正式 CI/CD、业务目标值、发布审批和值班机制尚未确认。
- 每日备份、自动调度和恢复脚本尚未启用，当前不具备正式 RPO/RTO 保证。

## R1：内部可用的文本 Agent 闭环（P0，当前目标）

目标：团队成员能在一个工作台内稳定完成 Agent 配置、保存 Revision、Chat 调试、发布和结果核对；发生问题时可以定位、回滚和恢复。

包含：

- Agent 草稿、不可变 Revision 和管理员调试链路。
- 发布应用显式绑定 Revision，支持激活、暂停和回滚。
- Usage 区分管理员调试与线上用户来源。
- Session 日志只展示企业终端用户会话，并可追溯到应用和版本。
- 连接、加载、空内容、无权限和失败状态真实可辨认。
- 对外发布的独立对话页和 Embed Chat 完成移动端响应式适配，不要求管理员工作台首版支持手机管理操作。
- 核心链路的自动化测试和人工验收证据。
- 内部环境具备明确的部署、备份、恢复和故障响应方法。
- 当前开发机重启后能够恢复 PostgreSQL 数据、管理员身份材料和应用版本关系。
- 进入内部日常使用前，每日自动本地备份成功，最近 14 天备份可追溯，能够在当前机器和备份介质仍可用时恢复到最近 24 小时内的数据状态。
- 20 个同时进行的文本对话可用，30 个同时在途轮次自动化门禁通过。

不包含：

- 复杂组织权限模型、审批流和计费系统。
- 完整 BI、CRM、模型训练和通用聊天产品能力。
- 未经验证的高并发生产承诺。
- 实时语音、数字人和面向外部客户的 SLA。

完成条件：

- [`QUALITY.md`](./QUALITY.md) 中 P0 门禁通过。
- 发布、暂停、回滚及版本追溯均有验收证据。
- 备份恢复和版本回滚至少完成一次演练，恢复结果包含数据库、Tenant、Agent、Revision 和应用版本关系。
- 核心失败场景不会展示伪造成功或示例数据。
- 团队成员可以按文档独立完成启动、使用、发布和常见故障恢复。
- 产品负责人确认管理员文本主链路可用于团队日常工作。
- 对外对话页在最新版稳定版电脑 Chrome、真实 Android Chrome 和真实 iOS Safari 中通过文本会话核心流程验收。

## R2：可嵌入、可运营的企业应用（P1）

目标：企业开发者能安全接入 Embed，运营与支持人员能定位线上问题。

包含：

- Embed bootstrap、凭据交换、Conversation、附件和实时连接。
- 允许来源、访问凭据、限流、租户隔离和日志脱敏。
- Embed SDK/iframe 的宿主集成与浏览器验收。
- 在已确认的移动浏览器范围内完成兼容性和真实设备回归。
- 发布后健康观察、故障分级、降级和回滚流程。
- 核心产品与系统指标的服务端采集。

完成条件：

- 独立宿主页和 Embed 页面通过浏览器验收。
- 已激活应用使用真实模型完成端到端对话验证。
- 容量、故障注入和安全测试达到确认后的目标值。
- [`RELEASE-SOP.md`](./RELEASE-SOP.md) 和 [`INCIDENT-SOP.md`](./INCIDENT-SOP.md) 经至少一次演练。

## R3：实时语音与数字人体验（P2）

目标：在不破坏文本主链路的前提下，提供可降级的实时语音和 Agent 形象反馈。

包含：

- Server 到 Voice Service 的受控调用和流式音频转发。
- Web 实时播放、取消、队列和状态反馈。
- Avatar 状态与 Agent 生命周期的稳定映射。
- TTS 失败自动保留文本对话能力。
- 冷启动、首包延迟、播放中断和 GPU 容量的可观察性。

完成条件：

- 文本、语音和 Avatar 状态在正常、取消、重连和失败场景下一致。
- Voice Service 不直接暴露给浏览器，凭据和用户文本不进入日志。
- 达到 [`METRICS.md`](./METRICS.md) 中确认后的语音体验目标。

## 后续候选（P2，未排期）

- 更细粒度的组织权限与发布审批。
- 多环境配置、灰度发布和自动化生产部署。
- 更完整的运营分析、成本预算和告警。
- VoiceDesign、Voice Clone、ASR 和麦克风输入。
- 第三方可独立集成的稳定 SDK 与契约版本策略。

## 待确认

- 每个阶段的目标发布日期或时间窗口。
- R2 对外阶段的预期租户数、并发连接数和日对话量。
- 局域网部署的目标机器、网络边界、域名/TLS 和访问控制方式。
